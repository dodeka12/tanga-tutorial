# MkDocs Documentation Site — Implementation Plan

> **Status:** plan only — not yet implemented.

Give `tanga-tutorial` a versioned documentation site published to GitHub Pages on
merge to `main`, mirroring the sibling repo [`../tanga`](../../tanga). The site
renders the existing Jupyter tutorials (`tutorials/`) and example scripts
(`examples/`) as pages.

---

## Goal

- A Material-for-MkDocs site whose `docs_dir` is a new top-level `docs/` folder.
- The root-level `tutorials/` (`.ipynb`) and `examples/` (`.py`) are pulled into
  the docs build via a **MkDocs copy hook** (chosen over symlinks / `docs_dir: .`;
  see Decisions).
- Docs are **versioned with mike**, exactly as `tanga` does — no custom version
  injection hook.
- `hatchling` + `hatch-vcs` provide dynamic versioning in `pyproject.toml`.
- GitHub Actions publishes docs to `gh-pages` on merge to `main` (plus a branch
  preview and an optional RC→stable promotion workflow).

---

## Reference (`../tanga`)

The pattern to mirror lives in the `tanga` repo:

| File | Role |
|------|------|
| `mkdocs.yml` | Material theme, `docs_dir: docs`, `extra.version.provider: mike`, MathJax |
| `pyproject.toml` | `hatchling` + `hatch-vcs`, `dynamic = ["version"]`, `[tool.hatch.version] source = "vcs"` |
| `docs/overrides/main.html` | `<title>` override |
| `docs/javascripts/mathjax.js` | MathJax TeX config |
| `.github/workflows/cd.yml` | push to `main` → RC tag → `mike deploy` + `mike set-default` |
| `.github/workflows/docs-preview.yml` | `workflow_dispatch` branch preview (`dev-<branch>`) |
| `.github/workflows/promote.yml` | RC → stable, `mike deploy --update-aliases <v> latest` + set default |
| `tools/version-tag.sh` | Conventional Commits → semver tag (`--rc` support) |

> **Note on the version hook:** `tanga` has a `docs/_hooks/inject_version.py`, but
> its `mkdocs.yml` does **not** list it under `hooks:` — it is disabled/unused.
> Versioning is handled entirely by **mike** (`extra.version.provider: mike` +
> `versions.json` on `gh-pages`). We follow the same approach: **no custom version
> hook**, mike only.

---

## Decisions

1. **Expose `tutorials/` + `examples/` via a MkDocs copy hook** that mirrors them
   into `docs/` at build time. Robust across Windows (dev) and Linux (CI); the
   generated copies are gitignored.
2. **mike** versions the docs (multiple versions live side-by-side under
   `gh-pages`, Material renders a version selector). No custom version hook.
3. **hatchling + hatch-vcs** for the project's dynamic version (git-tag derived,
   independent of mike's docs versioning).
4. **mkdocs-material** theme + **mkdocs-jupyter** (renders `.ipynb` and `.py`) +
   **jupytext** (mkdocs-jupyter needs it for `.py` files).
5. Notebooks are **rendered as saved** (`execute: false`, the mkdocs-jupyter
   default) — no re-execution during build, so CI never needs to compile tanga
   bindings.

## 1. `pyproject.toml`

Mirror tanga's build system and dev deps; keep the existing `tanga-py` dependency
and TestPyPI source untouched.

```toml
[build-system]
requires = ["hatchling", "hatch-vcs"]
build-backend = "hatchling.build"

[project]
name = "tanga-tutorial"
dynamic = ["version"]          # was: version = "0.1.0"
# ...existing description/readme/requires-python/dependencies unchanged...

[tool.hatch.version]
source = "vcs"

[dependency-groups]
dev = [
    "jupyter>=1.0",
    "ipykernel>=6.29",
    "ipython>=8.30",
    "scipy>=1.13",
    "mike>=2.0",
    "mkdocs-material>=9.7.7",
    "mkdocs-jupyter>=0.24",
    "jupytext>=1.16",
]
```

Notes:

- `tanga-tutorial` ships **no Python package** (it's a tutorials repo). With the
  default hatchling wheel target and no packages found, `uv sync` installs a
  metadata-only editable distribution — sufficient for
  `importlib.metadata.version("tanga-tutorial")` if needed. If hatchling errors
  on the empty package set, pin `[tool.hatch.build.targets.wheel] packages = []`.
- `hatch-vcs` derives the version from git tags; with no tags yet it falls back
  to `0.0.0`. The docs version comes from **mike + git tags**, not from this value.
- The `tanga-py` dependency currently resolves from **TestPyPI** (an RC build).
  This is temporary — once published to **PyPI**, drop the
  `[tool.uv.sources]` / `[[tool.uv.index]]` entries and install `tanga-py`
  directly.

## 3. Copy hook — `docs/_hooks/copy_content.py`

MkDocs only serves content under `docs_dir`, so the root `tutorials/` and
`examples/` are mirrored into `docs/` before the build. The hook runs in
`on_config`, which fires **before** MkDocs collects files, so the copies are
picked up as pages. It removes the previous copy first so deletions propagate.

```python
# docs/_hooks/copy_content.py
"""Copy the root tutorials/ and examples/ into docs/ before the build."""

import shutil
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parents[2]   # docs/_hooks → docs → root
DOCS_DIR = REPO_ROOT / "docs"
_CONTENT = ("tutorials", "examples")

def on_config(config, **kwargs):
    for name in _CONTENT:
        src = REPO_ROOT / name
        dst = DOCS_DIR / name
        shutil.rmtree(dst, ignore_errors=True)    # clear stale copies
        if src.is_dir():
            shutil.copytree(
                src,
                dst,
                ignore=shutil.ignore_patterns(
                    ".ipynb_checkpoints", "__pycache__", "*.pyc", ".git"
                ),
            )
```

Known limitation: `on_config` runs once per invocation, so during `mkdocs serve`
an edit to `tutorials/`/`examples/` requires restarting `serve` (the `watch`
config still triggers a rebuild of already-copied files). `mkdocs build` (CI) is
always a fresh copy. If full live-reload is wanted later, move the copy to an
`on_files` hook and register the copied files — a documented refinement, not part
of the initial implementation.

## 5. Versioning with mike (no custom hook)

`extra.version.provider: mike` tells mike/Material to render the version selector.
mike builds each version into its own `gh-pages` subdirectory and maintains
`versions.json`; versions never overwrite each other.

| Command | Result |
|---|---|
| `mike deploy --push vX.Y.Z-rcN` | build + push under `vX.Y.Z-rcN/` |
| `mike set-default --push vX.Y.Z-rcN` | make it the root-URL default |
| `mike deploy --push --update-aliases vX.Y.Z latest` | move the `latest` alias |
| `mike list` | list versions + aliases |
| `mike delete dev-<branch> --push` | remove a preview |

Local dev:

- `uv sync --group dev` then `mkdocs serve` — content preview (no version
  selector, since mike isn't injecting version data).
- `mike serve` / `mike serve -a` — versioned local preview.

## 6. GitHub workflows

New folder `.github/workflows/`. Mirror tanga but **drop the wheel-publishing
jobs** (tanga-tutorial publishes no package). Bot identity is set for the
`gh-pages` pushes.

### 6.1 `docs.yml` (on push to `main`)

Mirrors tanga's `cd.yml` pipeline minus `publish-wheels`:

```
version-bump → push-tag → docs-deploy
```

- `version-bump`: `./tools/version-tag.sh --rc --dry-run` → next RC tag, emitted
  as a job output (guard: skip on `workflow_dispatch` / bot pushes).
- `push-tag`: `git tag -a "$TAG" ...` + `git push origin "$TAG"`.
- `docs-deploy` (needs `push-tag`):
  1. checkout (`fetch-depth: 0`, `fetch-tags: true`)
  2. `git config user.name/email` (bot)
  3. `astral-sh/setup-uv@v5` + `uv sync --group dev`
  4. `git fetch origin tag "$TAG"`
  5. `uv run mike deploy --push "$TAG"`
  6. `uv run mike set-default --push "$TAG"`

Permissions: `contents: write`.

### 6.2 `docs-preview.yml` (manual)

Mirrors tanga's `docs-preview.yml`: `workflow_dispatch` → deploy current branch
under `dev-<branch>` (sanitize `/` → `-`), print preview URL
`https://dodeka12.github.io/tanga-tutorial/dev-<branch>/`.

### 6.3 `promote.yml` (manual, optional)

Mirrors tanga's `promote.yml` **docs portion only** (no PyPI publish): promote the
latest RC tag to a stable tag, then
`mike deploy --push --update-aliases "$VERSION" latest` +
`mike set-default --push latest`.

## 7. Interactive "play" buttons (Colab & Binder)

MkDocs has no turnkey "launch button" config (unlike Jupyter Book) — but the
buttons are just URLs, so we add them ourselves. Two launch targets:

| Service | URL pattern |
|---|---|
| Colab | `https://colab.research.google.com/github/dodeka12/tanga-tutorial/blob/main/<path>.ipynb` |
| Binder | `https://mybinder.org/v2/gh/dodeka12/tanga-tutorial/HEAD?filepath=<path>.ipynb` |

`<path>` is the repo-relative notebook path (e.g.
`tutorials/algebra/01_quick_tour/01_quick_tour.ipynb`). Because the copy hook
mirrors `tutorials/` → `docs/tutorials/` and `examples/` → `docs/examples/`,
MkDocs' `page.file.src_path` already equals the repo path, so the URL can be
built generically.

### 7.1 Render the buttons (template override)

Extend `docs/overrides/main.html` to inject the two buttons on notebook pages:

```html
{% extends "base.html" %}

{% block htmltitle %}
  ...existing title override copied from tanga...
{% endblock %}

{% block content %}
  {% if page.file.src_path.endswith(".ipynb") %}
    <div class="launch-buttons">
      <a class="md-button" href="https://colab.research.google.com/github/dodeka12/tanga-tutorial/blob/main/{{ page.file.src_path }}" target="_blank">Open in Colab</a>
      <a class="md-button" href="https://mybinder.org/v2/gh/dodeka12/tanga-tutorial/HEAD?filepath={{ page.file.src_path }}" target="_blank">Launch Binder</a>
    </div>
  {% endif %}
  {{ super() }}
{% endblock %}
```

(Jinja attribute verified during implementation; optionally gate on a
`page.meta` frontmatter flag instead of the `.ipynb` suffix.)

### 7.2 Colab — environment setup

"Open in Colab" loads only that single `.ipynb`; it does **not** install the
repo's dependencies. So each tutorial notebook needs a guarded setup cell near
the top (guarded so the local `.venv` path is a no-op):

```python
import importlib.util
if importlib.util.find_spec("pytanga") is None:
    # Temporary: TestPyPI rc. Final form is simply:
    #   %pip install "tanga-py[examples]"
    %pip install --extra-index-url https://test.pypi.org/simple/ "tanga-py[examples]==0.11.0rc1"
```

Colab is Linux x86_64, so the precompiled Linux wheel serves E3/PGA3/etc. with
**no compiler**; Colab also ships a compiler anyway, so even a custom algebra
works (first use just compiles ~5–20 s). (Add `--pre` if pip ever refuses the rc.)
Once `tanga-py` is on PyPI, the cell becomes `%pip install "tanga-py[examples]"`
— no index, no rc pin, no `--pre`.

### 7.3 Binder — environment setup

Binder builds its environment from the repo, so add these at the repo **root**
(Binder reads these files, not `uv.lock`/`pyproject.toml`):

`requirements.txt` (temporary — TestPyPI rc):

```
--extra-index-url https://test.pypi.org/simple/
tanga-py[examples]==0.11.0rc1
```

Once `tanga-py` is on **PyPI**, this simplifies to a single line:

```
tanga-py[examples]
```

`apt.txt` — only if a custom algebra is needed (not the standard five):

```
g++
```

For the standard algebras the precompiled Linux wheel means **no compiler** and
no `apt.txt`.

### 7.4 Precompiled-wheels / compiler notes (from tanga docs)

- The wheel bundles precompiled extension modules for **five** algebras: E3,
  P3/PGA3, N3 (float64), E3 modular (int64), and G(10,0) sparse (int64).
- Import resolution is: cache hit → precompiled match (copy + load, **no
  compile**) → JIT compile (needs the `[compile]` extra **and** a C++ compiler).
  The standard algebras stop at the precompiled step.
- Precompiled wheels are documented for **Linux x86_64** and **Windows
  (win_amd64)** — so Colab/Binder (Linux) are covered; macOS is not documented.
- A precompiled binary is skipped if its cache key no longer matches the bundled
  C++ headers (self-healing for users who do have a compiler).
